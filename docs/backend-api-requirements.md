# 云工作空间 · 后端接口要求（可交付版）

**给谁**：AI Coding 平台服务端的同事。
**要什么**：按本文实现/对齐接口；本文只写**服务端要提供什么**，不要求你们了解 DSH 前端或插件内部。

**一句话背景**：插件**复用 DSH 自己的前端**（会话渲染、右侧文件树与预览都是 DSH 官方组件），
所以服务端只需把「会话与 LLM 输出」「云端文件」「工作空间与运行」这些**内容**通过 HTTP/SSE 提供出来。
**把平台输出映射成 DSH 的会话事件由插件侧的 Host 完成** —— 你们不需要模仿 DSH 的任何事件名。

依据：`docs/cloud-workspace-reuse-design.md`（复用架构与机制验证结论）、
`插件-云工作空间设计说明书.md` §5/§7（既有页面数据流与错误规则）。

---

## 1. 总原则（每条都影响前端行为）

| # | 原则 | 为什么 |
| --- | --- | --- |
| 1 | **服务端是唯一权威**：状态机、授权、revision、时间都以服务端为准 | 插件不做本地状态机推断，也不把失败改写成成功 |
| 2 | 客户端只拿**不透明 ID、非敏感摘要、短期 URL**；**永不**下发远程物理路径、模型密钥、Token 正文 | 设计说明书 §7；插件不持有也不显示这些 |
| 3 | 每个写操作带 **`Idempotency-Key`**；竞争资源带 **`If-Match`** 或 **`expected_revision`** | 重试不得产生重复副作用；冲突必须显式 |
| 4 | 统一错误 envelope：`{ code, message, request_id, data }`；**前端按 `code` 分类，不解析 `message` 文案** | 文案会变、会本地化；分类必须稳定 |
| 5 | 每个集合与每条流都要有**分页 / 增量 / 续传** | 会话可能很长；断线必须能接着读 |
| 6 | 未知枚举值必须落到**显式的未知状态**，不得回落为"正常/可运行" | 前端据此决定是否允许操作 |
| 7 | **不得用空结果代替失败**（下游故障时报错，不返回空列表） | 「没有数据」与「读不到数据」是两件事，混淆会掩盖故障 |

## 3. 需要补齐的能力（按前端面分组）

### 3.1 会话与 LLM 输出 —— **全新，最重要**

**前端面**：DSH 的会话界面（消息、推理、工具卡、审批、计划、流式输出都由 DSH 渲染）。
**因此服务端要提供的是"可被映射成会话事件"的语义**，而不是 UI 数据。

| 需求 | 具体要求 |
| --- | --- |
| **会话身份** | 一个云工作空间 ↔ 一个会话；返回稳定、不透明的会话 ID；换账号/换项目不得复用 |
| **事件流** | 每条事件带：**单调递增序号**、类型、时间戳、负载；可选带幂等事件 ID |
| **必须能区分的语义** | ① **轮次与步骤的边界**；② **助手文本增量与推理增量分开**；③ 工具调用的 **ID / 名称 / 参数（允许增量）**，以及**结果与调用的配对**；④ **终止原因**：正常 / 取消 / 超长 / 错误；⑤ **审批请求与审批决定**；⑥ **重试**（含重试链） |
| **续传** | 客户端带「最后收到的事件 ID/序号」重连 → 从该点继续；**无法续传时必须显式告知**（而不是从中间接上） |
| **历史分页** | 打开一个已有会话时可按页向前取历史（前端有窗口化装配） |
| **失败语义** | 区分三类：**可重试的下游失败** / **需用户介入**（审批）/ **终态失败**；每类都有稳定 code |
| **时间** | 所有时间戳以服务端为准（客户端不做时间推断） |

> ⚠️ 这一条是**新增工作量最大**的部分，也是"复用 DSH 会话界面"能不能成立的关键。

### 3.2 云端文件（右侧栏的文件树与预览消费）

| 需求 | 具体要求 |
| --- | --- |
| 目录树 | 给定路径返回条目：名称、类型（文件/目录）、大小、**etag**、**revision**；支持分页或增量 |
| 文件内容 | 内容 + 内容类型 + 大小 + **etag** + **revision**；大文件需分页或流式 |
| **可显示性声明** | 明确哪些类型**可直接预览**（文本 / Markdown / JSON / 图片 / 静态 HTML）；**HTML 必须同时给出 CSP 与 sandbox 声明** |
| 短期预览 URL | 服务端签发、**绑定该工作空间**、带过期时间；客户端不接受用户输入的任意 URL/端口 |
| 变更基线 | 当前 revision 与基线 revision（供 diff 与冲突判断） |
| 路径规则 | 一律返回**工作空间相对路径**；不得返回远程物理路径 |

### 3.3 工作空间

- 列表/详情：仅返回**项目授权范围内**的资源；状态机取值固定
  （`draft` / `provisioning` / `starting` / `ready` / `degraded` / `stopping` / `stopped` / `failed` / `archived` / `deleting`），
  未知值必须显式未知；
- 生命周期：启动/停止/重试/归档/删除 —— 请求带 **revision + 幂等键**；
  **冲突 / 忙碌 / 无权 / 服务不可用各有稳定 code**；
- 代码源与分支候选来自服务端（不由前端拼接）。

### 3.4 运行（Run）

- 创建：绑定 工作空间 + 会话 + Agent 配置版本 + 写模式 + **期望 revision**；
- 状态：`queued` / `starting` / `running` / `waiting_approval` / `succeeded` / `failed` / `canceled` / `expired`，未知显式未知；
- 取消 / 重试：**重试产生新 run ID** 并带 `retryOfRunId`，不覆盖原 run；
- **写入型 run 的服务端 lease**：同一工作空间已有写入 run 时返回 `WORKSPACE_BUSY` 与当前 run 摘要
  （前端**不得**静默排队或改为本地执行）；
- 审批：等待审批可由前端展示，**审批结果仍由服务端鉴权与记录**。

### 3.5 身份与授权

- 项目授权：**"无权"与"不存在"必须可区分**（当前实现对非成员返回 **404 + `PROJECT_NOT_MEMBER`**，
  以避免泄露项目是否存在 —— 这个策略保留，前端按 **code** 分类）；
- 会话过期：可识别 → 前端走重新登录，而不是显示空数据；
- **稳定 code 词汇表**（至少）：`UNAUTHORIZED` / `FORBIDDEN` / `PROJECT_NOT_MEMBER` /
  `NO_ORGANIZATION_ACCESS` / `RESOURCE_NOT_FOUND` / `REVISION_CONFLICT` / `WORKSPACE_BUSY` /
  `VALIDATION_ERROR` / `SERVICE_UNAVAILABLE`。

## 4. 通用要求（每条都可验收）

| 要求 | 理由 | 验收方式 |
| --- | --- | --- |
| `Idempotency-Key` 覆盖所有写操作 | 重试不产生重复副作用 | 同键重发 → 同一结果，无第二次副作用 |
| `If-Match` / `expected_revision` 覆盖竞争资源 | 并发写必须显式冲突 | 两个并发写 → 一个成功、一个 `REVISION_CONFLICT` + 当前 revision |
| 稳定错误 envelope（`code`/`message`/`request_id`） | 前端按 code 分类 | 注入故障，检查 code 与 request_id 可关联日志 |
| 分页/增量/续传 | 长会话与大目录 | 中途断开重连 → 不丢不重 |
| 服务端时间为准 | 客户端不做时间推断 | 响应带服务端时间基准 |
| 不下发敏感内容 | 设计说明书 §7 | 响应体扫描：无 Token / 密钥 / 远程物理路径 |
| 未知枚举显式未知 | 前端据此禁用操作 | 返回一个未定义状态值 → 前端显示"未知"且不可操作 |

---

## 5. 服务端**不需要**做的事

- **不需要**模仿 DSH 的会话事件名或任何 DSH 内部结构（映射由插件 Host 负责）；
- **不需要**知道 DSH 的槽位、布局或前端组件；
- **不需要**提供 UI 状态（当前选中的工作空间、打开的文件、面板布局等都由浏览器侧持久化）。

---

## 6. 自测场景（建议后端按此验收）

1. **断线续传**：流中途断开 → 带最后事件 ID 重连 → 事件不丢不重、序号连续；
2. **无法续传**：服务端重放窗口已截断 → **显式**返回"需重读快照"，而不是静默从中间接；
3. **revision 冲突**：并发写 → `REVISION_CONFLICT` + 当前 revision，前端保留用户输入；
4. **权限**：非成员读项目 → `404 PROJECT_NOT_MEMBER`；无管理权写 → `403 FORBIDDEN`；
5. **空 vs 失败**：下游故障 → 报错（带 code），**不得**返回空列表；
6. **未知状态**：返回一个未定义的状态值 → 前端显示"未知"且不提供操作；
7. **工作空间忙碌**：已有写入 run 时创建第二个 → `WORKSPACE_BUSY` + 当前 run 摘要。
